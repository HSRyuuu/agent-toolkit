# 보고서

독자가 읽고 판단·승인·투자를 결정하는 문서. 운영안, 제안, 진척 보고, 조사 결과에
기반한 실행 요청이 여기 속한다.

## 여는 블록

제목 밑 한 문장 요약 다음에 `구분 | 내용` 2열 표를 둔다. 아래에서 이 문서에
해당하는 항목만 고른다.

| 항목 | 언제 넣나 |
| --- | --- |
| 문서 목적 | 항상 |
| 공유 대상 | 항상 |
| 작성 주체 | 조직·팀 단위 문서일 때 |
| 시행 시점 | 실행을 요청하는 문서일 때 |
| 대상 기간 | 성과·진척 보고일 때 |
| 문서 상태 | 초안·검토·확정을 구분해야 할 때 |

## 섹션 순서

해당하는 것만 고른다. 자료에 없는 지표·리스크를 채우려고 섹션을 만들지 않는다.

1. **배경** — 지금 왜 이 판단이 필요한지. 한두 문단.
2. **하려는 것** — 무엇을 하겠다는 건지 단정형으로.
3. **성과 기준** — 무엇을 보고 성공을 판정하는지. 숫자와 측정 방법.
4. **실행 계획** — 기간별 또는 우선순위별. 표가 잘 맞는다.
5. **리스크와 중단 조건** — 어떤 지표가 나빠지면 멈추는지.

3번과 5번이 보고서를 보고서로 만든다. 빠지면 그냥 소개 문서다.

## 유형 특유 안티패턴

**활동량을 성과로 제시** — 발송 건수, 작업 개수, 회의 횟수는 활동이지 성과가
아니다. 대신 그 활동이 만든 변화를 지표로 쓴다.

**숫자 없는 목표** — "개선한다", "강화한다"는 판정이 불가능하다. 대신 값과 기한을
붙이거나, 아직 모른다면 언제까지 기준선을 정하겠다고 쓴다.

**리스크 섹션 누락** — 좋은 면만 있으면 결정자가 검증을 못 한다. 대신 중단 조건을
먼저 적는다.

**배경이 자기 정당화로 김** — 배경이 본문보다 길면 결정이 아니라 설득이 목적인
문서가 된다. 대신 배경은 판단에 필요한 사실까지만.

**대안 없이 하나만 제시** — 결정할 것이 없으면 보고서가 아니다. 대신 고려한
선택지와 고른 이유를 한 줄씩 적는다.
