# architecture — 마우스오버 팝업 아키텍처 지도

서비스·API 박스, 호출 화살표, 경로별 DB 읽기/쓰기, 외부 호출을 한 장의 SVG 지도로 그린다.
박스에 마우스를 올리면 상세 팝업이 뜨고, 클릭하면 고정되며 `Esc` 로 닫는다. 공통 규칙은 `../SKILL.md` 를 따른다.

- 템플릿: `templates/architecture.html`
- 예제: `examples/order-flow.json` (가상의 주문 흐름, 모든 기능을 한 번씩 쓴다)
- `kind` 는 생략하거나 `"architecture"` 로 쓴다.

## 데이터 스키마

```jsonc
{
  "meta":  { "title": "제목", "ver": "2026-10-20", "hint": "머리말 안내(선택)",
             "okLabel": "확정된 호출", "unkLabel": "정확히 못 찾음",
             "confirmedLabel": "확인", "estimatedLabel": "추정" },          // 전부 선택. ver 기본값은 오늘 날짜
  "groups": [ {
    "id": "order", "title": "order-api", "sub": "부제(선택)",
    "col": 1,                      // 열 번호(0부터). 좌표는 자동 계산. x,y,w,h 를 직접 줘도 된다
    "kind": "focus",               // 선택: focus(파랑) | ext(주황, 외부) | queue(보라, 메시지)
    "nodes": [ {
      "id": "o_order", "label": "주문 생성", "method": "POST", "path": "/orders",
      "row": 2,                    // 행 번호(소수 가능). 같은 row 면 가로로 정렬된다
      "desc": "팝업 설명", "note": "팝업 하단 주석", "stub": false,   // stub=true 면 점선 박스(미확인 주체)
      "db": [ { "s": "shop.orders", "op": "W", "n": "설명", "e": "근거 파일명·메서드(줄번호 금지)", "c": 1, "g": "묶음 이름" } ],
      "ext": [ { "t": "결제 API  POST /charges", "n": "설명", "e": "근거" } ]
    } ]
  } ],
  "edges": [ { "n": "1", "from": "web_order", "to": "o_order", "kind": "ok", "note": "툴팁" } ],
  "foot": [ { "title": "읽는 법", "items": ["문장", "문장"] } ]
}
```

- `db[].op` 는 `R W U D` 의 조합이다 (읽기, insert, update, delete). 예: 읽고 갱신하면 `"RU"`.
- `db[].s` 가 `redis:키` 처럼 `접두어:` 로 시작하면 그 접두어(Redis, Opensearch …)로 묶고, 아니면 `DB` 로 묶는다. `g` 를 주면 그 이름이 우선한다.
- `db[].c` 는 확인 여부다. `1` 이면 "확인", `0` 이면 "추정" 라벨이 붙는다. 근거 수준을 모르면 생략한다(라벨 없음).
- `edges[].kind` 는 `ok`(실선, 기본) 또는 `unk`(회색 점선, 정확히 못 찾은 연결) 둘뿐이다. `n` 을 주면 번호 배지가 붙는다.
- 화살표 방향이 기본 규칙(가로/세로 자동)과 다르면 `fromSide`/`toSide`(`r l t b`), 겹치면 `offA`/`offZ`(px) 를 준다.

## 작성 규칙

- 받은 내용에 없는 DB 항목, 호출, 근거를 만들어 넣지 않는다.
- 확인하지 못한 호출자·발행자는 `stub` 노드와 `unk` 화살표로 그린다. 실선으로 그리지 않는다.
- 근거(`e`)는 파일명·클래스명·메서드명까지만 쓴다. 줄번호는 오류로 막힌다.
- 저장소 접근은 노드가 실제로 하는 것만 `db` 에 적는다. 모르면 `db` 를 비우고 `note` 에 "저장소 접근은 확인하지 않았다"처럼 밝힌다.
- 노드 `label` 은 사용자가 알아보는 이름으로 쓰고, 호출 지점은 `method`·`path` 에 쓴다.
- 새로 추가했지만 아직 배포 전인 노드는 `label` 에 `(신규)` 를 붙이고 `desc` 에 배포 전임을 쓴다.
- `foot` 는 읽는 법과 결론을 쓰는 곳이다. 이 내용은 하단 에이전트용 텍스트에 들어가지 않는다. 흐름 자체만 `desc`/`note`/`db`/`ext` 에 쓴다.

## 레이아웃

- 같은 `col` 의 그룹이 세로로 겹치면 `row` 를 1.5 이상 띄운다. `render.py` 가 `WARN:` 으로 알려 준다.
- 호출하는 쪽 그룹을 왼쪽 열, 호출받는 쪽을 오른쪽 열에 둔다. 화살표가 박스를 가로지르지 않도록 같은 흐름의 노드는 같은 `row` 에 맞춘다.
- 다른 그룹 박스를 지나는 화살표는 `fromSide`/`toSide` 로 방향을 바꾸거나 노드의 `row` 순서를 바꿔 피한다. 스크린샷에서 확인한다.

## 크기와 확대

- 지도 폭은 `viewBox` 폭을 CSS px 로 그대로 쓴다(`svg#map` 의 `width` 를 JS 가 지정). 브라우저 줌·핀치가 지도 크기에 반영되고, 화면보다 넓으면 지도 영역 안에서만 가로 스크롤한다.
- 지도 위의 `−` `+` `100%` `맞춤` 컨트롤은 같은 폭에 배율을 곱한다(40%~300%). `맞춤`은 화면 폭 100%이다.
- 템플릿을 고칠 때 `svg#map` 에 `width: 100%` 를 되살리지 않는다. 줌이 동작하지 않게 된다.
