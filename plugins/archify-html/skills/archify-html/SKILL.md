# archify-html

넘겨받은 내용을 **HTML 하나**로 만든다. 노드·화살표·DB 정보를 새로 조사하거나 추측하지 않는다.
내용이 부족하면 채워 넣지 말고 비워 두거나 미확인으로 표시한다.

## 하지 않는 것

- 코드 읽기, 위키·DB·로그 조회, 에이전트 병렬 감사 (필요하면 이 스킬 전에 다른 방법으로 끝낸다)
- 내용의 사실 여부 판단. 받은 그대로 옮긴다. 단, 앞뒤가 안 맞으면 만들기 전에 묻는다.
- 별도의 `archify` 스킬을 포함한 다른 다이어그램 도구 의존. 이 스킬은 자기 템플릿과 스크립트만 쓴다.

## 순서

1. **입력 정리** — 받은 내용을 아래 스키마의 JSON(`data.json`)으로 옮긴다. 산문으로 받았다면 노드, 화살표, DB 항목으로 쪼갠다.
2. **생성**
   ```bash
   python3 <skill>/scripts/render.py data.json out.html --shot check.png
   ```
   `--hash n=<노드id>` 를 같이 주면 그 노드의 팝업이 열린 상태로 찍는다. `--open` 은 브라우저로 연다. Chrome 이 없으면 스크린샷은 건너뛴다.
3. **확인** — 스크린샷에서 박스·화살표 겹침, 글자 잘림, 팝업 내용, 하단의 에이전트용 텍스트를 본다. 오류(`ERROR:`)가 나오면 JSON 을 고친다. `WARN:` 은 `row` 간격을 조정한다.
4. **전달** — 출력 경로와, 내용에서 미확인으로 둔 항목을 알린다. 요청이 없으면 커밋·공유는 하지 않는다.

예제: `<skill>/examples/order-flow.json` (가상의 주문 흐름, 모든 기능을 한 번씩 쓴다)

## 하단 에이전트용 텍스트

- 지도 아래에 `에이전트용 텍스트` 영역이 항상 생긴다. 구성 요소, 호출 관계, 경로별 저장소 접근, 확인하지 못한 연결을 평문으로 옮긴 것이다.
- `render.py` 가 **데이터에서 자동 생성해 HTML 소스에 그대로 넣는다.** 같은 내용을 따로 쓰지 않는다. JS 없이 파일을 읽는 에이전트도 `<pre id="agenttext">` 에서 읽을 수 있다.
- 사용자는 영역을 드래그해서 복사하거나 `전체 복사` 버튼을 누른다.
- `foot` 는 이 텍스트에 들어가지 않는다. 결론·해석·특정 이슈 얘기는 `foot` 에 쓰고, 흐름 자체만 `desc`/`note`/`db`/`ext` 에 쓴다. 그래야 텍스트가 흐름 설명만 담는다.

## 데이터 스키마

```jsonc
{
  "meta":  { "title": "제목", "ver": "2026-10-20", "hint": "머리말 안내(선택)",
             "okLabel": "확정된 호출", "unkLabel": "정확히 못 찾음",
             "confirmedLabel": "확인", "estimatedLabel": "추정" },          // 전부 선택. ver 기본값은 오늘 날짜
  "groups": [ {
    "id": "order", "title": "order-api", "sub": "부제(선택)",
    "col": 1,                      // 열 번호(0부터). 좌표는 자동 계산. x,y,w,h 를 직접 줘도 된다
    "kind": "focus",               // 선택: focus(파랑) | ext(주황, 외부) | queue(보라, 메시지)
    "nodes": [ {
      "id": "o_order", "label": "주문 생성", "method": "POST", "path": "/orders",
      "row": 2,                    // 행 번호(소수 가능). 같은 row 면 가로로 정렬된다
      "desc": "팝업 설명", "note": "팝업 하단 주석", "stub": false,   // stub=true 면 점선 박스(미확인 주체)
      "db": [ { "s": "shop.orders", "op": "W", "n": "설명", "e": "근거 파일명·메서드(줄번호 금지)", "c": 1, "g": "묶음 이름" } ],
      "ext": [ { "t": "결제 API  POST /charges", "n": "설명", "e": "근거" } ]
    } ]
  } ],
  "edges": [ { "n": "1", "from": "web_order", "to": "o_order", "kind": "ok", "note": "툴팁" } ],
  "foot": [ { "title": "읽는 법", "items": ["문장", "문장"] } ]
}
```

- `db[].op` 는 `R W U D` 의 조합이다 (읽기, insert, update, delete). 예: 읽고 갱신하면 `"RU"`.
- `db[].s` 가 `redis:키` 처럼 `접두어:` 로 시작하면 그 접두어(Redis, Opensearch …)로 묶고, 아니면 `DB` 로 묶는다. `g` 를 주면 그 이름이 우선한다.
- `db[].c` 는 확인 여부다. `1` 이면 "확인", `0` 이면 "추정" 라벨이 붙는다. 근거 수준을 모르면 생략한다(라벨 없음).
- `edges[].kind` 는 `ok`(실선, 기본) 또는 `unk`(회색 점선, 정확히 못 찾은 연결) 둘뿐이다. `n` 을 주면 번호 배지가 붙는다.
- 화살표 방향이 기본 규칙(가로/세로 자동)과 다르면 `fromSide`/`toSide`(`r l t b`), 겹치면 `offA`/`offZ`(px) 를 준다.
- 노드가 `col` 이 같은 그룹끼리 세로로 겹치면 `row` 를 1.5 이상 띄운다 (스크립트가 경고한다).

## 규칙

- 받은 내용에 없는 DB 항목, 호출, 근거를 만들어 넣지 않는다.
- **코드 줄번호는 쓰지 않는다.** 근거(`e`)와 설명 어디에도 `Foo.java:41`, `Foo.java:41-52` 형태를 넣지 않는다. 코드가 바뀌면 틀어지기 때문이다. 파일명·클래스명·메서드명까지만 쓴다(예: `OrderRepository.save`). 받은 내용에 줄번호가 섞여 있으면 지우고 만든다. `render.py` 가 이 형태를 오류로 막는다.
- 확인하지 못한 호출자·발행자는 `stub` 노드와 `unk` 화살표로 그린다. 실선으로 그리지 않는다.
- 키·토큰·비밀번호·개인정보는 팝업에 넣지 않는다. 받은 내용에 섞여 있으면 빼고 알린다.
- 문서를 수정해 다시 만들 때는 `meta.ver` 날짜를 그날로 올린다. 날짜를 안 주면 오늘 날짜가 들어간다.
- 결과 HTML 은 외부 의존이 없는 단일 파일이다. 템플릿을 바꾸지 않고 데이터만 바꿔 반복 생성한다.
