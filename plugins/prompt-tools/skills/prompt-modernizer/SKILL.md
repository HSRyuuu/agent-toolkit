# Prompt Modernizer

낡은 프롬프트에서 **최신 프론티어 모델 기준으로 고칠 만한 항목을 찾아내고, 각 항목의 개선안을 제시한다**. 판단 기준은 "짧게 만들기"가 아니라 모델이 이미 잘 하는 것에 대한 지시를 찾아내고, 모델이 알 수 없는 것에 토큰을 몰아줄 지점을 짚는 것이다.

**이 스킬은 진단 도구다. 대상 아티팩트를 수정하지 않는다.** 산출물은 항목별 판정과 개선안이 담긴 리포트 하나뿐이다. 실제 편집은 사용자가 리포트를 보고 별도로 요청했을 때만 한다.

전제: 최근 세대 모델은 추론·탐색·도구 선택을 내부에서 처리한다. 그걸 대신 지시하던 문장은 이제 성능을 **깎는다**. Anthropic은 Claude Opus 5 대상 Claude Code 시스템 프롬프트의 80% 이상을 제거하고도 자사 코딩 평가에서 측정 가능한 손실이 없었고, ETH SRI의 AGENTS.md 연구는 컨텍스트 파일이 성공률은 못 올리면서 추론 비용만 20%+ 늘렸다고 보고했다.

## 절대 완화하지 않는 것

먼저 잠근다. 아래에 해당하면 분류 대상에서 빼고 원문 그대로 둔다.

- 안전·권한·승인 게이트 (파괴적 작업 확인, 프로덕션 접근, 비밀정보 취급)
- 다운스트림 코드가 파싱하는 출력 계약 (JSON 스키마, 고정 마커, 종료 토큰)
- 법률·컴플라이언스·데이터 보존 문구
- 사용자가 "이건 유지"라고 명시한 항목
- **정체성 문장을 직접 구현하는 지시** (1절에서 확정한다). 그 지시의 경직성 자체가 기능인 경우다 — 분류 대상에서 뺀다

## 과잉 삭제 실패 모드

걷어낸 자리에 아무것도 넣지 않으면 아래가 나온다. 판정 중에 이 이름들을 떠올린다.

- **정체성 소거** — 모델 기본값을 거스르는 것이 목적인 지시를 "모델이 알아서 할 일"로 오판해, 다 지우고 나면 아티팩트가 존재할 이유가 사라진다. 이 스킬이 가장 자주 낼 고장이다.
- **조기 완료 선언** — 일부만 하고 끝났다고 보고한다. 완료 기준 없이 단계 목록만 지웠을 때 나온다.
- **자가 검증 편향** — 자기 결과물을 자기가 검증하고 통과시킨다. 검증 절차를 하네스로 옮기지 않고 그냥 뺐을 때 나온다.
- **제약 유실** — 긴 세션에서 요약이 반복되며 초반 제약이 사라진다. 상주해야 할 제약을 "중복"으로 오판했을 때 나온다.

Anthropic이 스킬에 대해 남긴 유일한 완화 경고: *"Avoid making them overconstrained, **except in highly important areas**."* 중요 영역의 경직성은 결함이 아니다. 중복은 다듬되 구조는 재건하는 것이지, 구조까지 걷어내는 게 아니다. (뒤의 세 실패 모드는 장기 에이전틱 작업에서 반복 보고되는 것이고, 근거 목록의 1차 자료에 명시된 문구는 아니다.)

**규칙: 대체물을 먼저 만들고 나서 원본을 뺀다. 대체물 없는 변환은 그냥 삭제다.**

## 작업 흐름

### 1. 인테이크

네 가지를 확정한다. 모르면 사용자에게 한 번에 묻는다.

- **대상 아티팩트**: 파일 경로 또는 붙여넣은 프롬프트
- **타깃 모델**: 벤더와 세대 (Claude 5 계열 / GPT-5.5+ / Gemini 3 등). 벤더별 판정이 갈리므로 필수. 4절 표에 없는 벤더면 가장 가까운 열을 쓰되 리포트에 *벤더 가이드 미확인*으로 표시한다.
- **검증 수단**: eval 세트, 골든 케이스, 아니면 "없음". 없으면 이후 리포트에 *미검증* 라벨을 붙이고 삭제 폭을 보수적으로 잡는다.
- **정체성 문장**: *"이 아티팩트가 없으면 모델이 무엇을 다르게 하는가"* — 아티팩트가 덮어쓰는 행동 **하나당 한 줄**, 최대 7줄. 사용자에게 확정받는다.

한 줄로 끝나는 경우는 단일 목적 프롬프트뿐이다. CLAUDE.md/AGENTS.md처럼 서로 무관한 규칙이 여러 주제로 섞인 파일은 **섹션당 최소 한 줄**을 뽑는다. 그러지 않으면 그 한 문장 밖의 규칙은 보호 장치가 0이고, 5절 무결성 패스가 무의미하게 통과한다.

정체성 문장이 필수인 이유: 이게 없으면 판정 질문이 "모델이 이걸 이미 하나?"로 좁혀지고, **모델의 기본 성향을 거스르는 것이 목적인 프롬프트는 전부 삭제 판정이 난다**. 과잉 설계를 막는 스킬을 예로 들면 문장 하나하나가 다 "모델이 알아서 할 일"처럼 보이지만, 그 문장 뭉치가 곧 기능이다. 정체성 문장이 있으면 질문이 *"이걸 지우면 저 줄이 약해지나?"*로 바뀐다.

### 2. 원자 단위 분해

프롬프트를 **하나의 지시 = 한 항목**으로 쪼갠다. 문단이 아니라 지시 단위다. 한 문장에 지시가 둘이면 둘로 센다. 이 목록이 리포트의 행이 된다.

### 3. 항목별 판정

각 항목을 네 버킷 중 하나로 분류한다. 판정 기준은 정체성 문장이다.

**우선순위: 정체성 문장이 아래 모든 표를 이긴다.** 어떤 행이 걸리더라도, 그 지시가 정체성 문장 중 한 줄을 직접 구현하고 있으면 잠금 항목으로 빼고 분류하지 않는다. 표를 먼저 적용하고 5절에서 되돌리는 순서가 아니다 — 애초에 분류에 넣지 않는다.

**측정할 수 없으면 유지가 기본값이다.** 아래 판정 중 A/B 실행이 필요한 것(*결과를 바꾸지 않는 예시*, 페르소나 행동 테스트)은 검증 수단이 "없음"이면 삭제 버킷에 넣지 않는다. 리포트에 *미측정*으로 표시하고 유지한다.

**삭제** — 모델이 이미 하는 일을 시키는 문장

| 패턴 | 근거 |
|------|------|
| "단계별로 생각해", "추론을 설명해" | 추론 모델이 내부에서 수행. OpenAI가 명시적으로 불필요하다고 안내 |
| 같은 규칙의 반복 노출 | 시스템 프롬프트·도구 설명·문서에 흩어진 중복은 토큰만 먹는다 |
| "오늘은 2026년 8월" 류 날짜 고지 | 하네스가 이미 주입하는 경우에 한함. 날것의 API 시스템 프롬프트면 유지 |
| 코드/파일 구조를 보면 아는 설명 | 모델이 읽으면 되는 것을 문장으로 옮긴 것 |
| 쓰지 않는 도구의 정의·설명 | 오선택 확률만 올린다 |
| 결과를 바꾸지 않는 예시 | 빼고 같은 출력이면 그건 장식이다 |

**변환** — 지우면 손실이지만 지금 형태가 낡은 것. 완화의 핵심 버킷이다.

| 지금 형태 | 바꿀 형태 |
|----------|----------|
| 상세 단계별 절차 ("1. X해라 2. Y해라") | 목적지 + 완료 기준. 경로는 모델이 고른다 |
| 경직된 "항상/절대" 규칙 — *사용자가 합리적으로 요청할 만한 것을 막는가?* **단 정체성 문장을 구현하는 규칙은 이 행의 대상이 아니다** — 막는 것 자체가 기능이면 유지 | 판단 원칙. 예: "주석 달지 마라" → "주변 코드의 주석 밀도와 관용구에 맞춰라" |
| 도구 사용 few-shot 예시 | 도구 파라미터·enum·설명 설계로 이관 — 예시가 탐색 공간을 그 모양으로 좁힌다. 도구 정의를 못 고치는 아티팩트(CLAUDE.md 등)면 한 줄 라우팅 규칙으로 압축 |
| 산문으로 쓴 명세 | 코드·테스트 스위트·루브릭 등 실행 가능한 레퍼런스 |
| 상주 컨텍스트에 올린 문서 전체 | Progressive disclosure. frontmatter/요약만 상시 노출, 조건 충족 시 본문 로드 |
| 산문으로 쓴 스타일 지시 ("간결하게") | API 파라미터 (`text.verbosity`, reasoning effort). 파라미터가 덮는 지시는 프롬프트에서 뺀다 |
| 매번 반복되는 검증 절차 문단 | 하네스로 이관 — 검증 스킬, 훅, CI 체크. 프롬프트는 *무엇을 왜* 검증할지만 남긴다 |
| 승인 규칙의 반복 | 판단 규칙 한 벌 + 안전한 동작 allowlist. 반복하면 예측 가능한 안전 행동에도 승인을 물어본다 |

**유지** — 모델이 추론할 수 없는 정보. 손대지 않는다.

목표와 결과 정의 · 성공 기준과 중단 조건 · 비즈니스/안전/권한 제약 · 맥락 의존적 도구 라우팅 규칙 · 출력 형태와 검증 요구 · 이 작업에만 필요한 선별된 근거 자료.

**충돌** — 서로 모순되는 지시쌍. 삭제가 아니라 **해소**가 필요하다.

전체 항목을 훑어 모순을 찾는다. 실제 사례: `"DO NOT add comments"`와 `"leave documentation as appropriate"`가 한 프롬프트에 공존. 모순은 모델을 둘 중 하나로 임의 붕괴시키므로, 우선순위 조항을 넣거나 한쪽을 지운다.

### 4. 벤더 편차 확인

**판정이 벤더마다 갈리는 항목**이 있다. 타깃 모델 기준으로 덮어쓴다.

셀에 "가이드 미언급"이라고 적힌 것은 해당 벤더 문서에 그 주제가 **없다**는 뜻이다. 없는 것을 있는 것처럼 사용자에게 말하지 않는다.

| 항목 | Anthropic (Claude 5) | OpenAI (추론/GPT-5.5+) | Google (Gemini 3) |
|------|---------------------|----------------------|-------------------|
| few-shot 예시 | 도구 사용 예시는 제거 — 블로그는 도구 예시만 다룬다. 출력 형태 예시는 *추론*(문서에 판정 없음) | zero-shot 먼저, 필요할 때만 추가. 지시와 어긋나는 예시는 해롭다 | **항상 포함 권장**. 형식·범위 통제용으로 명시적으로 권장 |
| CoT 유도 문구 | 가이드 미언급 | 불필요, 명시적 비권장 | 내부 사고 자동 생성. 단계 유도는 선택적 |
| 길이 제어 | 가이드 미언급 | `text.verbosity` 파라미터 우선, 작업별 요구는 프롬프트에 | **기본이 간결**. 더 상세·대화체가 필요하면 프롬프트에서 명시적으로 요구 |

샘플링 파라미터는 Gemini만 판정이 있다 — `temperature`/`top_p`/`top_k`를 **기본값으로 두라고 강하게 권고**하며, 건드리면 루프·성능 저하가 난다고 경고한다. 다른 두 벤더의 해당 가이드에는 샘플링 내용이 없다.

Gemini 대상 프롬프트에서 few-shot을 걷어내는 것은 벤더 가이드에 정면으로 반한다. 벤더 확인 없이 일괄 삭제하지 않는다.

**페르소나/역할 부여는 벤더 판정 대상이 아니다.** 행동 변화로 판정한다 — 빼고 넣었을 때 출력이 실제로 다르면 **유지**(그게 이 프롬프트의 기능이다), 같으면 **삭제**(장식이다. "당신은 전문 개발자입니다" 류). 어느 벤더 문서도 페르소나 제거를 요구하지 않는다. 최신 가이드에 안 보이는 것과 제거 권고는 다르다. 단 Gemini는 배치를 규정한다 — System Instruction 또는 프롬프트 맨 앞.

### 5. 무결성 패스

개별 판정이 전부 옳아도 합계가 틀릴 수 있다. 삭제·변환을 모두 적용한 결과물을 상상하고 두 가지를 확인한다.

1. **정체성 유지** — 그 결과물이 인테이크의 정체성 문장을 **줄 단위로 하나씩** 여전히 만족하는가. 한 줄이라도 만족하지 않으면 삭제로 분류한 항목 중 어느 것을 유지로 되돌려야 하는지 지목한다.
2. **결손** — 정체성 문장을 만족하려면 필요한데 원본에 처음부터 없는 것. 버킷이 아니라 별도 목록으로 나열한다. 흔한 결손:
   - 완료 기준과 중단 조건 (단계 목록만 있고 "언제 끝인가"가 없는 경우)
   - 검증을 맡을 하네스 지목 (검증 스킬, 훅, CI)
   - CLAUDE.md/AGENTS.md의 코드베이스 gotchas — repo 목적은 가볍게, 함정 위주로

이 패스는 모델이 자기 삭제 결정을 자기가 채점하는 구조다 (위 *자가 검증 편향*). 그래서 스스로 확정하지 않고 결과를 리포트에 올려 사용자가 확정한다.

### 6. 마이그레이션 절차

한 번에 다 고치면 무엇이 원인인지 알 수 없다. 리포트에 이 순서를 지시로 넣는다.

1. 모델만 교체하고 프롬프트·reasoning effort는 그대로 둔 채 성능 기준선 측정
2. 삭제 버킷을 **묶음 단위로** 제거 — 전부 한 번에 아님. 묶음 = 같은 삭제 근거를 공유하는 행들(예: "모델 내부 처리" 전체, "중복 노출" 전체). 한 묶음이 10행을 넘으면 쪼갠다
3. 각 묶음마다 재측정. 회귀가 나오면 **그 묶음을 되돌려 회귀를 먼저 멈춘 뒤**, 원문 복원이 아니라 회귀를 잡는 최소 지시로 교체한다
4. 변환 버킷은 삭제가 안정화된 뒤에 착수

eval이 없으면: 대표 작업 3~5개를 골라 before/after 출력을 나란히 비교하는 것으로 대체하고, 그 한계를 리포트에 적는다.

### 7. 리포트 출력 (스킬의 종착점)

리포트를 내는 것으로 이 스킬은 끝난다. 원본은 읽기만 하고 손대지 않는다.

```markdown
## 프롬프트 현대화 리포트
- 대상: <경로> | 타깃 모델: <모델> | 검증: <eval 있음/없음>
- 정체성 문장 (이게 유지되어야 한다)
  1. <아티팩트가 덮어쓰는 행동 1>
  2. <행동 2>
- 요약: 분류 대상 N개 지시(잠금 제외) → 삭제 A · 변환 B · 유지 C · 충돌 D

리스크 = 되돌리기 난이도 × 회귀 시 영향 (낮음/중간/높음). 벤더 칸은 4절이 판정을 덮어쓴 경우만 채운다.

| # | 현재 지시 (요약) | 판정 | 이유 | 대체안 | 벤더 | 리스크 |
|---|-----------------|------|------|--------|------|--------|
| 1 | "단계별로 생각해" | 삭제 | 모델 내부 처리 | — | — | 낮음 |
| 2 | 배포 절차 7단계 | 변환 | 경로 고정이 유연성 제약 | 완료 기준 + 중단 조건 | — | 중간 — 회귀 시 3번 항목부터 복원 |
| 3 | "주석 금지" ↔ "문서화는 적절히" | 충돌 | 임의 붕괴 | 우선순위 조항 추가 | — | 낮음 |
| 4 | 출력 형태 few-shot 3개 | 유지 | Gemini는 few-shot 항상 권장 | — | Gemini 역전 | — |

## 무결성
- 정체성 문장 줄별 유지 여부: <1번 예 / 2번 아니오 — 근거>
- 유지로 되돌린 항목: <# 목록, 없으면 "없음">

## 결손 (정체성 유지에 필요한데 원본에 없는 것)
- <항목과 이유. 없으면 "없음">

## 잠금 (미분류)
- <안전/권한/출력계약/정체성 구현 항목 나열>

## 미측정 (검증 수단이 없어 판정 보류, 전부 유지)
- <항목. eval이 있으면 이 블록은 생략>

## 적용 순서
1. ... (묶음별 제거 순서와 각 묶음의 검증 방법)
```

리포트 끝에 다음 행동을 사용자에게 넘긴다: *"적용할 항목 번호를 알려주면 그것만 반영한다."* 사용자가 번호나 범위를 지정하기 전에는 편집하지 않는다 — "전부 적용해줘"도 명시적 요청으로 친다. 편집 요청을 받으면 그때 원본이 git에 커밋되어 있는지 먼저 확인한다 (되돌릴 수 없으면 백업본을 남긴다).

## 사용자 프롬프트를 개선할 때

파일이 아니라 "모델에게 뭐라고 시킬지"를 다듬는 요청이면, 위 분류 대신 아래 형태를 권한다. 지시를 늘리는 대신 모델에게 **모르는 것을 찾게 시키는** 방향이다.

- `"애매한 부분을 한 번에 한 질문씩 인터뷰해 줘. 내 답이 아키텍처를 바꿀 질문 우선으로."`
- `"내가 뭘 모르는지 모르는 영역을 짚어주는 블라인드 스팟 패스를 해 줘."`
- `"구현 계획을 쓰되, 내가 가장 바꾸고 싶어할 결정부터 앞에 놓아줘."`
