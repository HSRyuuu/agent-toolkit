# docs — 사람이 관리하는 프로젝트 문서

템플릿을 복사하는 데서 끝내지 않는다. **코드로 확인되는 섹션은 분석한 내용으로 채우고**, 코드로 알 수 없는 섹션만 사람이 채우도록 남긴다.

## 대상

| 문서 | 원본 | 기본 위치 |
| --- | --- | --- |
| `PROJECT_OVERVIEW.md` | `templates/docs/PROJECT_OVERVIEW.md` | 문서 디렉토리 |
| `DB_SCHEMA.md` | `templates/docs/DB_SCHEMA.md` | 문서 디렉토리 |
| `DEPLOY.md` | `templates/docs/DEPLOY.md` | 문서 디렉토리 |
| `DESIGN.md` | `templates/docs/DESIGN.md` | 문서 디렉토리 |
| `ADR.md` | `templates/docs/ADR.md` | 문서 디렉토리 |

문서 디렉토리는 규약 §5와 프로필로 정한다.

## 절차

1. 사용자가 고른 문서만 대상으로 한다.
2. 템플릿을 복사하고 `{PROJECT_NAME}`과 설치 안내 주석을 처리한다.
3. 아래 채우기 표에 따라 섹션을 채운다. 근거 파일을 읽고 확인한 사실만 적는다.
4. 코드로 알 수 없는 섹션은 템플릿의 `<...>` 안내를 남긴다. 사용자가 그 자리에서 답할 수 있는 짧은 질문(한 줄 정의, 현재 단계 등)은 설치 중에 모아서 한 번에 묻는다.
5. 해당 없는 섹션(백엔드 없는 프로젝트의 `## Backend` 등)은 지운다.
6. 진입점 `### 외부문서`에 행을 추가한다.

## 채우기 표

| 문서 | 코드에서 채우는 섹션 | 근거 | 사람이 채우는 섹션 |
| --- | --- | --- | --- |
| `PROJECT_OVERVIEW` | 기술 스택(Frontend/Backend/데이터/배포), 핵심 링크 중 저장소·배포 URL | 매니페스트, 프레임워크 설정, CI, 배포 설정 | 한 줄 정의, 문제 정의, 사용자, 현재 단계, 마일스톤, 팀 |
| `DB_SCHEMA` | ER 요약, 테이블 상세(컬럼·타입·제약·FK), Enum, 마이그레이션 목록 | 마이그레이션 SQL, `schema.prisma`, Entity/Model 클래스, Enum 정의 | 접근 범위(누가 읽고 쓰는가), 보존 정책 |
| `DEPLOY` | 아키텍처 개요, 플랫폼, 배포 트리거, 배포 정의 파일, 환경변수 **이름** 목록, CI 단계 | `.github/workflows/`, `Dockerfile`, `vercel.json`, `fly.toml`, IaC, `.env.example`, 코드의 env 참조 | 도메인, 서비스 계정, 모니터링, 롤백 절차 |
| `DESIGN` | 색상·타이포·간격·radius·breakpoint 토큰, 다크 모드 전환 방식, 공용 컴포넌트 목록 | `tailwind.config.*`, CSS 변수, 테마·토큰 파일, 공용 컴포넌트 디렉토리 | 시각적 분위기, Do/Don't, 에이전트 프롬프트 가이드 |
| `ADR` | 코드로 드러나는 큰 결정의 **후보 목록**만 (프레임워크, DB, 모듈 분리 방식) | 매니페스트, 디렉토리 구조 | 각 결정의 배경·대안·결과. 후보는 사용자 확인 후에만 ADR로 적는다 |

## 하지 말 것

- 환경변수·시크릿의 **값**은 적지 않는다. 이름과 용도만 적는다.
- 테이블이 많으면(30개 이상) 모두 펼치지 않는다. 핵심 도메인 테이블만 상세히 쓰고 나머지는 이름 목록으로 둔다.
- 추측을 사실처럼 쓰지 않는다. 확인하지 못한 값은 `<...>`로 남긴다.

## 충돌

같은 이름의 문서가 있으면 유지 / 백업 후 교체 / 빠진 `##` 섹션만 추가 / 취소 중에서 묻는다. `ADR.md`는 번호와 인덱스가 깨지기 쉬우니 섹션 병합을 하지 않는다.

## 검증

```bash
python3 <skill>/scripts/check_harness.py "$TARGET"
```

`{PROJECT_NAME}` 잔존과 매핑 누락이 없어야 한다. INFO의 `<...>` 개수는 사용자에게 남은 일로 보고한다.
